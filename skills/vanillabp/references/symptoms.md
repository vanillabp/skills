# From a symptom to the answer

A developer searches with what they see, not with the name of the chapter that holds the
answer. This page maps the messages and exceptions which come up around VanillaBP onto the
place which explains them.

Read the *What you see* column like a search. Messages are shortened to the part worth
searching for, so match on the words rather than on the whole line. Where several rows fit,
read them in order: the first one is the common case.

The last group holds problems VanillaBP does not cause. They come up so often in its
neighbourhood that leaving them out would send people to Stack Overflow for an answer that
exists here.

Keep this list growing. A change which introduces a new message or a new startup check adds
its row here, next to the section it wrote.

## While the application starts

| What you see | What it is | Where it is answered |
|---|---|---|
| `No VanillaBP BPMS adapter found in classpath!` | A workflow module was found but nothing that could run its workflows. | [BPMS adapters](https://github.com/vanillabp/adapter-platform-integration/wiki/BPMS-adapters#what-happens-if-you-forget-the-adapter) |
| `UnsatisfiedResolutionException: Unsatisfied dependency for type io.vanillabp.spi.process.ProcessService` | On Quarkus: the core extension is missing from the module which builds the application, so no VanillaBP code took part in the build. | [Quarkus integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Quarkus-integration#if-the-extension-is-missing-quarkus-reports-it-not-vanillabp) |
| `Several VanillaBP adapters were found in classpath` and a demand for `prioritized-adapters` | Two adapters can run your workflows and nothing says which one goes first. Naming the order is most of a migration setup. | [Spring Boot integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Spring-Boot-integration#several-bpms-naming-the-order-is-the-whole-configuration), [Quarkus integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Quarkus-integration#several-bpms-naming-the-order-is-the-whole-configuration) |
| `Environment variables addressing the … configuration were NOT taken over by the configuration binding` | An environment variable can only override a property which is already there. The message names the ones it dropped. | [Spring Boot integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Spring-Boot-integration#overriding-configuration-via-environment-variables), [Quarkus integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Quarkus-integration#overriding-configuration-via-environment-variables) |
| `There is no workflow module descriptor file …`, or on Quarkus `No workflow module descriptor … was found in any valid location` | The `META-INF/workflow-module` marker is missing or sits in a JAR nothing looks at. | [Workflow modules in Spring Boot](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-modules-in-Spring-Boot#defining-a-workflow-module), [Workflow modules in Quarkus](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-modules-in-Quarkus#defining-a-workflow-module) |
| `No BPMN resources were found for workflow module …`, with the locations it searched | The BPMN files are not where VanillaBP looks for them. Nothing of that module can start. | [Workflow modules](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-modules#where-vanillabp-looks-for-bpmn-files) |
| `VanillaBP does not know how to persist the workflow aggregate …` | The aggregate has no repository of a persistence VanillaBP serves. | [Workflow aggregates](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-aggregates#persistence-technologies-supported) |
| A WARN that an aggregate `shares EVERY attribute with the BPMS` | Nothing carries `@NoSyncWithBPMS`, so every field of your business object leaves for the engine. | [Workflow aggregates](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-aggregates#fine-grained-control-over-attributes-synchronized-to-the-bpms) |
| A refusal saying that `the workflow names itself twice and the two names disagree` | The business key the BPMS holds and the id of the aggregate say something different. | [Starting workflows](https://github.com/vanillabp/adapter-platform-integration/wiki/Starting-workflows#a-workflow-started-past-vanillabp) |
| `The phase-two outbox table … does not exist!` or `The task-delivery table … has no column …` | The two tables VanillaBP owns were not created, or a migration is behind. | [Spring Boot integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Spring-Boot-integration#creating-the-tables-with-liquibase-or-flyway), [Quarkus integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Quarkus-integration#creating-the-tables-with-liquibase-or-flyway) |
| A WARN that an adapter may deliver a task more than once while `no TaskDeliveryLog is available` for the aggregate | Without that record a repeated delivery runs your handler again. | [Spring Boot integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Spring-Boot-integration#what-vanillabp-remembers-about-delivered-tasks), [Quarkus integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Quarkus-integration#what-vanillabp-remembers-about-delivered-tasks) |
| The boot ends naming a `@WorkflowTask` method and a transaction annotation on it | Your own transaction boundary changes what a `TaskException` does to the aggregate, so VanillaBP refuses to start. The message names the ways out. | [Workflow tasks](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-tasks#your-own-transaction-annotation-breaks-this-contract) |
| A warning about a transaction annotation your platform ignores, often `javax.transaction.Transactional` | The annotation fell out with the move to the Jakarta namespace and now declares a boundary which exists nowhere. | [Workflow tasks](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-tasks#your-own-transaction-annotation-breaks-this-contract) |
| The boot ends naming two classes and two different BPMN processes for one aggregate | One workflow aggregate has one `ProcessService`, so one process is the one `startWorkflow` starts. A second process belongs into `secondaryBpmnProcesses`. | [Workflow tasks](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-tasks#wiring-validation-at-startup), and rule 8 of [rules.md](rules.md) |
| The boot ends naming a BPMN task which has no `@WorkflowTask` method, or a method which matches no task | Both directions of the wiring are validated at every start. The message names the task, the process, the module and the fix. | [Workflow tasks](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-tasks#wiring-validation-at-startup) |
| The boot names a `@WorkflowTask` method which is not `public`, or one which overrides an annotated method | Neither is wired. VanillaBP reads public methods, and Java does not inherit a method annotation. | [Workflow tasks](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-tasks#a-handler-method-vanillabp-does-not-see) |
| A WARN per workflow module naming BPMN processes which nothing claims | Either the model of somebody else travelled in the same file, or a workflow service never became a bean. On Spring Boot the message names the classes it found. | [Workflow tasks](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-tasks#a-process-in-the-file-which-nothing-serves) |
| On Quarkus the build fails naming a class which carries `@WorkflowService` and is no bean | The build knows its bean set, so this never reaches a start. | [Workflow modules in Quarkus](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-modules-in-Quarkus#a-workflow-service-which-is-no-bean-stops-the-build) |
| An aggregate attribute of type `java.util.Calendar` stops the boot | Its text is the debug form of the implementation and carries no value. Share an `Instant` instead. | [Workflow aggregates](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-aggregates#what-is-shared-and-when) |
| A WARN naming the BPMN elements which can put a second token into a workflow | The aggregate of that process has no version attribute, so a lost write would go unnoticed. | [Workflow aggregates](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-aggregates#what-vanillabp-does) |
| A WARN naming an extension whose handler may save your aggregate | Same condition, other writer. The extension is a second writer on an aggregate which cannot notice one. | [Extensions](https://github.com/vanillabp/adapter-platform-integration/wiki/Extensions#what-an-extension-may-do-to-your-workflow-aggregate) |
| `The adapter id '…' is NOT configured any more, but it still has waiting phase-two outbox entries` | Either the id was renamed, which costs the workflows, or a BPMS was removed while it still had work. | [BPMS migration](https://github.com/vanillabp/adapter-platform-integration/wiki/BPMS-migration#naming-adapter-ids-and-never-renaming-them) |
| `WARN Version '1' of BPMN process '…' is still deployed at adapter …` | Your BPMS still holds a version of the model which your code no longer serves. | [Workflow tasks](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-tasks#the-versions-your-bpms-still-holds) |
| An adapter ends the boot naming a VanillaBP artifact and a version to raise | The BOM of your build is older than the adapter needs, and Maven applied that downgrade silently. | [Spring Boot integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Spring-Boot-integration#aligning-versions-the-vanillabp-bom), [Quarkus integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Quarkus-integration#aligning-versions-the-vanillabp-bom) |
| A WARN naming two of your workflow modules and the name they share | Two modules deploy the same identifier, and the mode which keeps them apart is not in use. | [Workflow modules](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-modules#when-two-of-your-own-workflow-modules-share-a-name) |
| A WARN that identifiers reach the BPMS as they are, offering `accept-unscoped-identifiers` | `name-clash-avoidance: none` keeps nothing apart. Acknowledge it once where the names really are unique. | [Workflow modules](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-modules#how-name-clashes-are-avoided), plus the *Keeping workflow modules apart* section of your adapter |
| A WARN naming a deployment of a name which was there before yours | The BPMS already holds that identifier. It may well be your own deployment from an earlier run. | [Workflow modules](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-modules#and-what-the-bpms-already-holds) |
| The boot ends asking for `vanillabp.workflow-modules.<id>.election.guessing-adapters` | One of the adapters cannot ask its BPMS whether it holds a workflow, so it would win every election. | [BPMS migration](https://github.com/vanillabp/adapter-platform-integration/wiki/BPMS-migration#adapters-which-can-only-guess) |
| The boot ends because no outbox can be resolved | The first-priority adapter of a process needs the two-phase start. The message names the remedies. | [Spring Boot integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Spring-Boot-integration#configure-the-transaction-outbox), [Quarkus integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Quarkus-integration#configure-the-transaction-outbox) |
| A line naming the extension methods which were wired and the keys each one serves | Read it when a method of yours is never called. It is either not in the line or in it under a key nobody offers. | [Extensions](https://github.com/vanillabp/adapter-platform-integration/wiki/Extensions#what-the-start-says-about-them) |

## While a workflow runs

| What you see | What it is | Where it is answered |
|---|---|---|
| `TaskException` | Not a failure. The error code routes the workflow through an error boundary event, and what the handler changed is committed. | [Workflow tasks](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-tasks#what-happens-when-my-handler-throws) |
| `WorkflowNotFoundException` | No configured BPMS knows the workflow. It was never started, started elsewhere, cleaned up, or a BPMS stayed silent. | [Viewing workflows](https://github.com/vanillabp/adapter-platform-integration/wiki/Viewing-workflows#errors) |
| `TaskNotFoundException` | No BPMS knows the task id. Usually an outdated id or a workflow which ended. | [Workflow tasks](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-tasks#completing-and-canceling-asynchronous-tasks) |
| `ProcessDefinitionNotFoundException` | The definition id is malformed, belongs to an adapter which is not configured any more, or names something the BPMS dropped. | [Viewing workflows](https://github.com/vanillabp/adapter-platform-integration/wiki/Viewing-workflows#errors) |
| Your handler ran a second time for the same task | Remote BPMS deliver at least once. VanillaBP answers a repeated delivery from its own record instead of running the handler again. | [Workflow tasks](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-tasks#a-repeated-delivery-does-not-run-your-handler-again) |
| An error naming the module, the process, the task and the handler, saying that nothing was persisted | A bean your handler called carries a transaction annotation which marked the transaction rollback-only. No startup check can see that one. | [Workflow tasks](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-tasks#your-own-transaction-annotation-breaks-this-contract) |
| An ERROR saying that whatever the run changed is gone, after a version conflict | The commit VanillaBP owns lost against a second writer on the aggregate. | [Workflow aggregates](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-aggregates#what-vanillabp-does) |
| `ObjectOptimisticLockingFailureException` or `OptimisticLockException` in a transaction of your own | The version attribute did its job. The retry belongs in your code, and it has to read the aggregate again. | [Workflow aggregates](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-aggregates#a-retry-you-can-write-down) |
| Work of one branch is gone, with no exception and no log line | Two writers on one aggregate and no version attribute. The blueprint `persistence-parallel-branches` shows the ways out. | [Workflow aggregates](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-aggregates#two-writers-on-one-aggregate) |
| A WARN that a task `has been waiting for its asynchronous completion` longer than configured | Nobody called `completeTask` for it. The record is there to be watched, and the message names the workflow. | [Workflow tasks](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-tasks#an-open-task-and-how-old-it-is) |

## Around the outbox

| What you see | What it is | Where it is answered |
|---|---|---|
| Nothing reaches the BPMS and the log is silent | A poller which has nothing to do sleeps until the next entry is due. Watch `vanillabp.outbox.pending` rather than the traffic. | [Observability](https://github.com/vanillabp/adapter-platform-integration/wiki/Observability#a-sleeping-outbox-looks-even-quieter) |
| An entry stopped being tried and waits for a person | It used up `block-after-attempts`. The page says how long the store tries and how to open the entry again. | [Spring Boot integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Spring-Boot-integration#how-long-it-tries-and-how-to-open-a-blocked-entry-again) |
| `Failed to update attempt count` from `TransactionOutboxImpl`, or an `UnexpectedRollbackException` out of a dispatch | A rejected attempt asked again inside a transaction which was already rollback-only. A rejected attempt ends now and the entry is planned again. | [Decision 49](https://github.com/vanillabp/adapter-platform-integration/blob/main/DECISIONS.md#49-a-dispatch-which-cannot-run-yet-ends-and-nothing-waits-inside-a-transaction) |
| A dispatch goes out later than the window the adapter asked for | The entry sits out its due time and then waits for the next poll. Name a window your BPMS really needs. | [ADAPTER-AUTHORS.md](https://github.com/vanillabp/adapter-platform-integration/blob/main/migration-adapter/ADAPTER-AUTHORS.md#about-time) |

| An INFO saying the cluster does not hold a task, before a completion fails | Camunda 8: the line says which of the two reasons it was, and it is the first thing to read then. | [Camunda 8 configuration](https://github.com/camunda-community-hub/vanillabp-camunda8-adapter/wiki/Configuration#when-a-task-is-unknown-to-the-cluster) |

| A `@WorkflowTask` method which matches no task is not reported | Camunda 7: the engine does not hand out what would be needed to check that direction. | [Camunda 7 deviations](https://github.com/camunda-community-hub/vanillabp-camunda7-adapter/wiki/Deviations#a-workflowtask-method-matching-no-task-is-not-reported) |
| A WARN naming a datasource: the embedded engine found several `DataSource` beans, or the one you named does not exist | Camunda 7 runs embedded and needs a database. | A WARN naming the `MIGRATION FALLBACK of VanillaBP 2.0` | Camunda 7: a sequence flow condition still reads the aggregate live, and that fallback will be removed. | [Camunda 7 configuration](https://github.com/camunda-community-hub/vanillabp-camunda7-adapter/wiki/Configuration#migrating-from-an-adapter-which-read-the-aggregate-live) |
| A WARN that the `IN-MEMORY MOCK` is the active Process-Engine-API implementation | Nothing is persisted, and every workflow is gone at shutdown. ## Problems VanillaBP only inherits

These come from your build, your container or your database. They show up around VanillaBP
often enough to be worth a row.

| What you see | What it is | Where it is answered |
|---|---|---|
| `NoSuchFieldError`, `NoSuchMethodError` or `AbstractMethodError` on a VanillaBP class after a version change | Two VanillaBP artifacts of different versions are on one classpath. The build stays green because a version your build manages wins silently. | [Spring Boot integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Spring-Boot-integration#aligning-versions-the-vanillabp-bom), [Quarkus integration](https://github.com/vanillabp/adapter-platform-integration/wiki/Quarkus-integration#aligning-versions-the-vanillabp-bom) |
| `BeanDefinitionOverrideException` for `aggregateRepository` | Two workflow modules met in one application and their repository beans carry the same name. | [Workflow modules in Spring Boot](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-modules-in-Spring-Boot#publishing-a-workflow-module-it-brings-its-own-wiring) |
| `conflicts with existing, non-compatible bean definition of same name` | The same collision for the classes a module has once per use case. Name those beans. | [Workflow modules in Spring Boot](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-modules-in-Spring-Boot#publishing-a-workflow-module-it-brings-its-own-wiring) |
| `Duplicate entity name` | One persistence unit cannot hold two entities called `Aggregate`. | [Workflow modules in Spring Boot](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-modules-in-Spring-Boot#publishing-a-workflow-module-it-brings-its-own-wiring) |
| `Not a managed type` for your aggregate | Nothing scanned the entity of that workflow module. | [Workflow modules in Spring Boot](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-modules-in-Spring-Boot#publishing-a-workflow-module-it-brings-its-own-wiring) |
| On Quarkus a workflow service in a sub-module is never found | The sub-module builds no Jandex index, so its classes are invisible to the augmentation. | [Workflow modules in Quarkus](https://github.com/vanillabp/adapter-platform-integration/wiki/Workflow-modules-in-Quarkus#provide-index-for-workflow-modules) |
| Quarkus warns that the profile of a native binary differs from the one it was built with | Some of what a native image holds was decided at build time. The warning is worth reading. | [Native images](https://github.com/vanillabp/adapter-platform-integration/wiki/Native-images#what-a-profile-decides-once-the-image-is-built) |
